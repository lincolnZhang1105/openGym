# OEM 训练场景与入门计划

基线：上游 v1.4.4，继承 `CHINESE_FIRST.md` 的中文优先改动。
功能分支：`feature/oem-training-setup`；Android：`1.4.4-oem.2` / versionCode `33`。

## 用户入口与行为

首页最上方「我的训练方式」→「继续」或「编辑」。四步流程：

1. 家中、健身房、家中和健身房。双场景分别设置器械；确认页选择当前场景。
2. 家中默认纯徒手；健身房预选常见器械，全部预选项直接可见且可取消。
   常用项为哑铃、弹力带、壶铃、训练凳、单杠；可以展开完整器械表。
   哑铃区分单只和一对，重量通过既有「设置 → 器械」补充。
   安静训练默认在家中开启，排除名称明确标识的跳跃、跑动等动作。
3. 综合体能、增肌、减脂；新手、恢复训练、规律训练；每周 2/3 天；15/25/40 分钟。
4. 展示每个场景的全身入门计划、动作、组数/次数/每侧次数、估计时长，再保存或保存并开始。

未确认时只修改组件草稿。取消不写入 store。新功能通过首页卡片引导，不强迫已有用户重做设置。
旧入门计划、自建计划、进阶模式仍可使用。没有删减原有模块。

## 计划与数据规则

- 每个场景提供一份可重复训练的全身入门计划；这是规则推荐，不是调用大模型生成。
  在明确的动作候选中按器械选择，单臂动作沿用上游「总次数 + 每侧」语义，平板支撑按时间记录。
  纯徒手背部内容是控制练习，页面明确说明无法等价替代负重划船。
- 时长包括约 5 分钟热身和组间转换/休息的粗估，按时间预算减少组数。
  实际时长仍取决于节奏与休息。初始负重为 0，由用户选择；默认关闭自动加重。
  这不是伤病康复处方，也未实现复杂周期或差异化减脂课程。
- 新增计划不改写旧计划、历史训练、日历覆盖、进行中的周期或轮转。
  普通周计划只填充没有有效训练安排的星期，默认周一/周四或周一/周三/周五。
  双场景只为当前场景填空闲日，另一个场景可直接从首页开始。
- 同一器械档案下完全相同的动作配置重复确认会复用计划；用户改过的计划保留，另建一份推荐计划。
- 场景切换改变器械筛选与库存，不重写周计划。启动不匹配的旧计划时显示提示，用户仍可明确继续。
  正在训练时禁止从 OEM 入口切换场景或重新确认设置。

## 源码入口与持久化

- `frontend/src/oem/TrainingSetup.jsx`：设置流程；`TrainingCard.jsx`：首页入口与切换。
- `frontend/src/oem/training.js`：纯推荐、保存、场景切换。
- `api/coach/core/oem-equipment.js`：前端与 Coach 共用的 OEM 器械条件。
- `frontend/src/oem/coach-equipment.js`：AI 建议在用户接受时再次验证当前器械条件。
- 上游接入点：App 路由、Home 卡片、`equipment.exAvailable`、`sheets.startFlow`、Coach 的构建/校验/应用。

不增加另一套全局器械状态。使用上游 `equipProfiles`，每项增加：

```js
oemTraining: {
  v: 1,
  scene: 'home', location: 'both',
  goal: 'general', experience: 'new', days: 3, minutes: 25,
  quiet: true, dbCount: 'single', routineId: '...'
}
```

生成的 routine 只有关联元数据 `oemTraining: {v: 1, profileId}`，训练本身仍是普通 routine。
沿用 `activeEquipId`、`equipFilterOn` 和 `gym-inventory` 的库存切换。
新档案初始化独立库存，不误继承上一个健身房的哑铃；旧档案和库存保留。
完整 JSON 备份包含这些字段；前后端既有逐项字段合并/打戳保留未知字段，无需新增顶层同步规则。
旧客户端能够保存字段，但不会执行 OEM 场景限制，因此不要把旧客户端当作同等功能版本。

## 器械与 AI 一致性

- OEM 档案显式携带 `body weight`，避免 Coach 把空数组当作「没有限制」。
- 当前 OEM 场景优先于 Coach 问卷中陈旧的器械、目标、经验、天数、时长；个人备注仍保留。
- 新候选、生成结果校验以及接受建议时均检查器械。历史动作可以出现在分析上下文中，
  但不能因为历史里出现过就绕过新动作的器械校验。
- `scripts/build-coach-assets.mjs` 把 catalogue 已有的附加需求 `nd` 带入精简动作表；
  生成文件 `api/coach/core/library-data.js` 随源码提交。没有更改图片或动画。
- 两端共用 `nd` 与名称规则识别训练凳、单杠、球等条件；不支持配置的台阶/箱子/双杠等器具从 OEM 筛选结果中保守排除。
  单只哑铃只显示明确单侧或双手持一只的动作。完整动作库仍可显式查看。
- 上游元数据并非逐项专业审校，名称推断也不等于完整器械标注。
  健身房按器械类别配置，不代表已盘点每一种固定器械。后续应继续完善 catalogue 的结构化需求，
  不要扩展为「所有动作已经精确适配」的承诺。
- 同时修复 `cleanPlan` 未传递请求时钟给 `programmesOut` 的旧问题，避免同一 AI 请求的周期周数读取不同日期。
